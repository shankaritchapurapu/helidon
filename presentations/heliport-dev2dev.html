Maven governance

Establish the Helidon Maven model before runtime migration

Heliport configures

  • Java 25 compiler and toolchain settings
  • Helidon and OCI/Talon BOM imports
  • Helidon runtime and feature dependencies
  • service-registry annotation processing
  • generated-source prerequisites
  • logging implementation and plugin management

Heliport checks before cleanup

  • explicit versions versus managed versions
  • old Dropwizard, Jersey, Jetty, and Netty dependencies
  • compatibility libraries still referenced by code
  • plugin and enforcer conflicts
  • feature modules not used by the application
  • parent or multi-module dependency-management conflicts
Dependencies are removed only after their use is checked. A Netty or Jackson artifact remains when source, generated code, or tests still require it.

OpenAPI processing

Keep generated OpenAPI and handwritten code aligned

Heliport migrates together

  • generated APIs and models
  • handwritten implementations
  • tests and fixtures

Heliport reports

  • service-side generated sources that still expose JAX-RS, Servlet, or old resource-base APIs
  • handwritten implementations that no longer match the generated Helidon contract

Helidon supplier

@Service.Singleton

final class ClockSupplier

Provider methods and named bindings can become service-registry suppliers when construction and scope are clear.

Behavior Heliport preserves

A feature family is complete only when every part has migrated

Incomplete integration

  • Talon module added while the Guice provider still constructs the client
  • new config keys written while Java still reads the Dropwizard DTO
  • binding removed before named consumers migrate
  • legacy dependency removed while generated or test code still uses it
  • tests still bootstrap the Dropwizard feature runtime

Complete integration

  • Talon module added only for an integration the application uses
  • Talon constructs and injects the standard client or service
  • new configuration is consumed by the integration
  • legacy construction is removed or explicitly retained
  • tests and validation exercise the migrated feature
If any part remains: Heliport preserves required compatibility and reports the developer action instead of marking the feature complete.

Runtime

Platform

Contracts

Operations

  • logging sinks and rotation

Tests

  • workflow drivers
  • fixtures for unresolved behavior
Owner frontier is Heliport's term for behavior without a proven safe target. The action plan names the next step: service-team decision, authorized Codex repair, or Heliport enhancement.
