# Oracle Swagger Code Generation Maven Plugin

This Maven plugin can be used to generate Java JaxRS service and model code based on Swagger 2.0 Specifications.

The model classes are based entirely on the Public SDK code generator, and will look like what our public Java SDK users would see.

The Swagger parser and generator use the Public SDK genenerator and add a few extra things necessary for service stub generation.

# Config Options
## Model config options
Models are generated by the public SDK.  You can find out what options there are available by looking at their options:
https://bitbucket.oci.oraclecorp.com/projects/SDK/repos/bmc-sdk-swagger/browse/bmc-sdk-swagger/src/main/java/com/oracle/bmc/sdk/swagger/codegen/OracleJavaSdkCodegen.java#60

By default, service codegen:
- Enables 'enableDefaultDiscriminatorOnlyElseNone' - this is used to prevent defaulting of polymorphic types to a specific class type unless the spec explicitly says there's a default (for backwards compat).
- Disables 'useExplicitlySetFilter' - this is an annotation for how to process serialization.
- Sets 'loggerName' to "log" - this is used by lombok to generate the logger name.
- Enables 'enableValidation' - this adds all the validation annotations to the models and service stubs.
- Enables 'enableEnumFromString' - this lets dropwizard deserialize enums with underscores correctly.

## Service options
These are options used during service generation.
- 'enableValidation' (default true) - same as models, it will enable all the validation annotations
- 'generateTaggedResponseForEtagHeader' (default true) - makes any api that returns an 'etag' header return a 'TaggedResponse' class object so you can add the etag
- 'contextsIdentity' (default true) - adds the OCI Identity args (auth context and principal) to every api
- 'contexts*' (default false) - these are various other flags to inject other different types of contexts, see OracleJavaJaxRsServiceCodegen.ConfigOption enum for more info.
- 'serviceGenSkipDeprecatedAbstractResources' (default false) - if enabled, stops generating the old abstract classes and only produces the configurable abstract class (which uses the contexts* config options).  this lets you configure and produce abstract resource handlers in a way that your project doesn't have any compile time dependencies on internal libraries.

The generated service stubs currently result in 5 different abstract classes you can extend from.  It is recommened you extend from 'Abstract<yourservice>BaseResource'.  This is the latest version that allows you the most ability to customize the injected contexts.

# Troubleshooting

## My generated code doesn't compile!
Try Slack channel #oci_commons.  If it complains of spec parsing, try channel #oci_api_guidelines, possibly your spec doesn't meet API guidance.

## Feature requests
This project is community owned.  Feature requests are done by forking the repository, making the necessary changes, and sending out a PR.  
New features must be backwards compatible, so make them opt-in, not opt-out.

## The code generator or parser doesn't work correctly
The underlying generator is owned by the public SDK team.  If you think there's a problem with it, reach out in Slack channel #oci_public_sdks, or
file a Jira ticket in the DEX bucket.
